## 1. Goal

From the tool window, see every MCP server the session has (claude.ai connectors included), with its state and error, and act on it as the CLI's own `/mcp` menu allows: disable, enable, reconnect, authenticate (the browser flow the CLI cannot start on its own in stream-json, probes 2.3). Typing `/` in the composer lists the session's commands as Desktop does; `/mcp` opens the panel instead of producing the one-line reply of `tandem-03`; `/model`, `/permissions` and `/mode` open Tandem's own pickers; every other command goes to the CLI, and a command the CLI runs locally shows as a notice, not as a reply bubble with a `Worked for 0s` footer. Hard rules: nothing on the EDT (every request, poll, payload decode and the browser launch run in the session's scope on `Dispatchers.IO`/`Default`), no credentials (Tandem never sees a token; the CLI does the OAuth), every CLI error visible, no "Claude Code" in a string, nothing personal in committed files. Section 12 adds the owner's second request of the same day: a composer line starting with `!` runs as a shell escape in the user's login shell, its output shown in the chat and fed to the CLI in the terminal's own shape, so Claude answers it.

## 2. Non-goals (what waits, and where)

- Adding or removing servers from the IDE (`mcp_set_servers`, probes 2.4): decoded and fixture-tested here (hard rule 6), no sender and no UI. Tandem must then remember what it added (probes 3.3).
- Tandem's own MCP server (the edit tools, `docs/design.md`): when it exists it reports as `dynamic`; this spec only reserves its name (`TANDEM_MCP_SERVER`, 4.2, recognised with `source == "dynamic"`) and renders it read-only.
- Rendering elicitation (`control_request elicitation`, `system/elicitation_complete`; **docs only**, `sdk.d.ts` 3976-3999, never recorded, probes 2.3). The wire does not change: Tandem keeps today's answer, the generic `Unsupported request: elicitation` error (`ClaudeSession.kt:294-297`), and only adds a WARNING notice `An MCP server asked for input Tandem cannot show yet.`, which decodes no field of the request, so a server's sign-in request (`mode:"url"`, this feature's own use case) is never refused silently (hard rule 5). The `{"action":"decline"}` answer probes 3.1 item 7 recommends and naming the server from `mcp_server_name` are both docs-only shapes with no fixture: they wait for a recording (11 item 12; hard rule 6 asks a fixture test for every protocol change). Test: 9.2.
- Using `tool_use_meta` in rows: it is decoded (`ToolUseMeta`, 4.1; decision 3) and fixture-tested (`mcp-tool-call:34`, 9.1), but no row reads it yet; MCP tool rows keep the `<server>: <tool>` label of `chat/ToolLabels.kt`.
- `mcp_oauth_callback_url`, `mcp_clear_auth`, `redirectUri` on `mcp_authenticate`, `claude mcp login/logout` from the IDE, `/login` (hard rule 3), `system/notification` toasts, `commands_changed` (docs only: accepted as `Unknown`, logged, 7), per-server token cost (`get_context_usage`), MCP prompts (`mcp__<server>__<prompt>`) in the palette, queued prompts while a turn runs, `/mcp <args>` text forms (unrecorded; sent as text, 3.4).
- Bash mode (12): interactive commands and a PTY (no TTY: `vim`, `top` or a `sudo` password prompt end at once or hang until Stop; stdin is closed), reading `respondToBashCommands` from the CLI's own settings files (`docs/protocol.md` 11.5: Tandem reads none; the Tandem setting of 12.4 stands in for it), `Ctrl+B` backgrounding, a shell escape while a turn runs (refused as any Enter is, 12.6), Windows beyond `cmd /c` (unverified, no CI), the TUI's own output limits and exit-code wording (unmeasured, bash probes open question 2), and aliases and functions from `.zshrc`/`.bashrc` (the command runs in a non-interactive login shell, 12.4, 12.9 item 6).

## 3. What the user sees

### 3.1 Header button and badge

At the right end of the session header row (`SessionHeader`, after the title): an `IconButton` with `Icon(AllIconsKeys.Webreferences.Server, contentDescription = "MCP servers")` and, beside it in the footer size (base 4.2, body − 1, `text.info`), the badge text `<connected>/<total>` (`3/5`), counting every server the session reports, disabled ones in the total. Tooltip `MCP servers: 3 of 5 connected`. Before the first `system/init` of a process and for a stopped session with no known servers the badge reads nothing and the tooltip `MCP servers`; `0/0` is never drawn. The badge updates from the thin list of every `system/init` (`mcp-status:6`) and from every `mcp_status` answer; it costs no request. Click or Enter toggles the panel. The button (and its badge) is drawn only when a session is selected, like the title; with no session the header is as today. It is the header's last focusable and carries an `mcpFocus` `FocusRequester`: the dimmed chat's `onEnter` redirect for `FocusDirection.Previous` (`TandemToolWindow.kt:185-190`, today straight to `newSessionFocus`, the header's `+`) targets `mcpFocus` when the button is drawn, else `newSessionFocus`, so Shift+Tab from the drawer's `New session` reaches `MCP servers` before the header's `+` (4.4; 9.5 updates the existing focus test).

### 3.2 The MCP panel

A sheet over the chat (the drawer pattern of `TandemToolWindow`: the drawer's own scrim, `Color.Black` at alpha 0.4 in a dark theme and 0.2 in a light one (`TandemToolWindow.kt:240`), click on the scrim closes, Esc closes; precedence drawer → MCP panel → slash palette → open card → running turn), anchored under the header, the chat column's width (`Modifier.chatColumn()`), height `min(60 % of the chat, content)`, scrolling in a `VerticallyScrollableContainer`. Focus: opening the panel moves focus to its first enabled action button, else `Close`; Esc there is handled by the panel's own `onPreviewKeyEvent`; closing returns focus to the composer. The scrim covers the whole chat `Box`, the composer included, as the drawer's does (`TandemToolWindow.kt:228-245`), so a mouse click there closes the panel, and the dimmed chat skips Tab as under the drawer (`focusProperties` `onEnter`, `:185-192`). `composerKey(panelOpen = true)` maps Esc to `ClosePanel` ahead of `CardEscape` and `Stop` (4.4) only as a guard for focus that was already in the composer when `/mcp` opened the panel, so Esc never stops a turn while the panel is open.

Top row: `MCP servers · 3 of 5 connected` (one `Text`), `IconButton` `Refresh servers` (`Actions.Refresh`), `IconButton` `Close` (`General.Close`). While a refresh runs the title gets ` · Refreshing…`. A refresh that fails shows under the title, in `text.error`: `Could not list servers: <error>` (the CLI's text verbatim; a CLI that does not know `mcp_status` answers an error, `docs/protocol.md` 4.1 example `Unknown subtype`, unrecorded, or not at all) or `The CLI did not answer within 15 s.`, each with `Retry`; the rows stay as last known (the init's thin list). A success whose payload has no decodable `mcpServers` array is such a failure: `Could not list servers: the CLI's answer listed no servers` (4.2). The follow-up refresh after every row action is the controller's own `refresh()` (4.4), so its failure lands here too, never dropped (hard rule 5). A refresh that times out while a turn runs keeps the rows and shows the same timeout text: the CLI answers `interrupt` mid-turn (`interrupt.ndjson:13`), but whether it answers the `mcp_*` requests mid-turn is unrecorded (7, 11 item 13). Then the groups, in this order, a group drawn only when it has a row: `claude.ai connectors` (`source == "claudeai"`, fallback `config.type == "claudeai-proxy"`; docs only), `Project` (`project`; docs only, SDK types), `Local` (`local`; docs only, SDK types), `User` (`user`; non-fixture probe `mcp-list` only), `Plugins` (`plugin`; non-fixture probe `mcp-list` only), `Session` (`dynamic`, recorded `mcp-status:6`: `--mcp-config` servers and run-time additions, where Tandem's own server will sit), `Managed` (`managed`; docs only, SDK types), `Other` (anything else, the raw source as a plain `Text` pill, base 4.2 pill style, not a `Chip`). Rows in the CLI's order inside a group.

A row (≥ 40 dp, two lines): line 1 the display name (for a connector the name with `claude.ai ` stripped; the full name is what every request sends), the status label, `N tools` / `1 tool` when `tools` is present, `v<version>` when `serverInfo.version` is; line 2 in the editor style, `text.info`: `config.url`'s scheme, host and port only (`https://h:8443`: no user info, path, query or fragment; a hosted server can carry its key in the path), else `config.command` alone, without args (probes 3.3's detail line; args, user info, paths and query values can carry tokens and would show during a screen share, and M5r's redactor treats both as secrets; the full values never reach a log either, 4.2), else nothing; a third line in `text.error` whenever the entry has an `error`, whatever its status: the `error` text verbatim (probes 3.4: the raw `error` whenever present; recorded on `failed` only, `mcp-status:18`; whether `needs-auth`, `disabled` or other entries carry one, `session token rejected` for example, is unrecorded, 11 item 1). Actions as `OutlinedButton`s at the right, from the table, each with `contentDescription = "<Action> <name>"` (`Disable echo`). Names are config text: drawn verbatim as plain `Text`, one line, ellipsised, the full name in the tooltip; never Markdown.

| `status` (wire) | Label | Actions | Notes (every status: the error line whenever `error` is present, probes 3.4) |
|---|---|---|---|
| `connected` | `Connected` | `Disable` | tools and version shown; `Disable` is immediate (`mcp-status:19-20`) |

It is offered because the CLI's own `/mcp` menu offers it (probes 3.3); whatever the CLI answers shows in the row like any other answer (an error in `text.error`, a success through the refresh).

Tandem's own server (name `TANDEM_MCP_SERVER` and `source == "dynamic"`, 4.2) shows `Tandem's own server` on line 2 and no action. While one of the four requests runs on a row (`McpBusy`, 4.4), that row's buttons are replaced by the request's caption (`Disabling…`, `Enabling…`, `Reconnecting…`, `Starting sign-in…`) and every other row's buttons are disabled (7). The sign-in wait of 3.3 is not such a request: during it the waiting row shows `Waiting for the browser…` and `Cancel` (`contentDescription = "Cancel <name>"`, 3.7), and the other rows keep their buttons, so a second `needs-auth` row (the two connectors of `tandem-04`) can start its own wait beside the first: `mcpAuth` holds one wait per server, each with its own poll (4.2). Empty panel: `No MCP servers are configured for this session.` Stopped session: the last known rows greyed, no buttons, and `The session is not running. Send a prompt to start it, then manage its servers.` The controller watches `handle.status` (4.4): while it is `STOPPED` the rows grey and the actions hide, and the panel refreshes as soon as it leaves `STOPPED`, so a panel opened while `SessionManager.create` still attaches the process (`SessionSpawner.kt:88-121`) fills in by itself, and a process that exits while the panel is open greys it at once. A row action's timeout: `The CLI did not answer within 15 s.` (`30 s` for Reconnect) in the row, with `Retry`.

### 3.3 Authenticate, step by step

1. `Authenticate` → caption `Starting sign-in…`; `manager.startMcpAuth(id, name, open)` sends `mcp_authenticate {serverName}` (`mcp-status:40` answers at once with `authUrl`, no browser, no `system` line).
2. Success with an `authUrl` that `ControlPayloads.browsableUrl` accepts, and `requiresUserAction` not `false` (4.1: `java.net.URI` parses it, its scheme is `http` or `https`, its host is non-null; anything else → `Could not start sign-in: the sign-in link is not an http(s) URL`; the CLI's text is never trusted as a link, CLAUDE.md "Validate everything") → the manager (the whole of `startMcpAuth`, the send included, runs in `handle.scope` and the caller only awaits its result, so a caller cancelled with the panel, before or after the answer, cannot cut off the open, the poll or `mcpAuth`) calls `open(authUrl)` (the `BrowserOpener`: `BrowserUtil.browse` on `Dispatchers.IO`, never the EDT; the platform shows its own balloon if no browser opens), starts the poll in the session's scope and publishes `McpAuthWait(server, startedAtMillis, outcome = null)` under the server's name in `SessionHandle.mcpAuth` (one wait per server). The row shows `Waiting for the browser… · <elapsed>` (elapsed in `formatDuration`, ticking each second, from `startedAtMillis`) with a `Cancel` button. The poll sends `mcp_status` every 2 s for 3 minutes (4.2); a tick answered with an error or not at all (for example while a turn runs, 7) counts as no change and the next tick retries; `NotRunning` or `Ended` on a tick ends the wait (step 3). A success **without** `authUrl` (unrecorded: `mcp-status:40` has all six fields, and the SDK leaves the payload untyped; probes 3.1 item 2 treats every field as optional; a bare success with no payload, or a payload of another shape, is this case too, 4.2), or with `requiresUserAction: false` (unrecorded: the one recorded answer has `true`, `mcp-status:40`; `callbackExpected` is decoded and ignored): no browser; the manager refreshes once and reports what it finds: `connected` → `Signed in`; still `needs-auth` → `Could not start sign-in: the CLI sent no sign-in link`; anything else → that row.
3. Outcome, each one a caption for 5 s then the normal row: `connected` → `Signed in`; `pending` (unrecorded: perhaps the server reconnecting once the callback landed) is no outcome, the wait goes on; still `needs-auth` at 3 minutes → `Still needs auth after 3 minutes. Finish signing in, then press Refresh servers.` with `Authenticate` offered again (recorded: the status stays `needs-auth` until the callback lands, `mcp-status:41`; the callback completing is unrecorded, probes 2.3). `Reconnect` is not offered on that row (unless it showed the terminal hint of step 4): on a `needs-auth` server it only answers `Server status: needs-auth` (`mcp-status:37`), and whether it gets past that check once a sign-in completed is unrecorded (11 items 1–2). If a refresh still shows `needs-auth` after the browser said it is done, a new session connects with the stored sign-in (docs only, probes 2.5). `failed` → the failed row with its error; the name gone from `mcp_status` → the row disappears and the panel title gets ` · <name> is no longer configured` for 5 s; the session ended (`Ended`, or `NotRunning` once the process is gone) → `The session has ended.`; at 3 minutes with the latest tick failed → `Failed(lastError)`: the error in `text.error` (the CLI's text, or `The CLI did not answer within 15 s.`) with `Authenticate` offered again, and the ERROR notice; `Cancel` → polling stops, `Needs auth` again (the CLI's flow is untouched; a later `Authenticate` sends a new request, what the CLI does with two pending flows is unrecorded).
4. `mcp_authenticate` answered with an error (a CLI that does not know the subtype answers an error, `docs/protocol.md` 4.1 example `Unknown subtype`, unrecorded, or not at all; any other error text is the CLI's) → nothing opens; `Could not start sign-in: <error>` and, under it, for any source but `dynamic` (an unknown source included), `Run claude mcp login "<name>" in a terminal, then press Reconnect, or start a new session.`; from then on, for the rest of the session (`SessionHandle.mcpLoginHinted`, 4.2, so a reopened panel keeps it), the row offers `Reconnect` (`mcp_reconnect`) beside `Authenticate` (probes 3.4: the terminal hint, then Reconnect). A `dynamic` server comes from Tandem's `--mcp-config` or was added at run time (probes 2.1, 2.4), which a terminal `claude mcp login` reading the config files cannot know: its hint is only `Start a new session to try the sign-in again.`, and it gets no `Reconnect`. Its answer shows verbatim: `Server status: needs-auth` (`mcp-status:37`) means the login has not landed; a success goes through the refresh. The shell path and a Reconnect that succeeds after a terminal login are docs only and unrecorded (probes 2.3, 2.5: a running session needs a reconnect after a login, a new session connects by itself; 11 item 2). No answer in 30 s → `The CLI did not answer within 30 s.` with the same hint, chosen by source the same way.
5. Who tells the user: the manager posts every outcome but `Cancel` and the session's end as a chat notice through `handle.notice` (INFO `Signed in to <name>.`, WARNING `Sign-in to <name> did not complete within 3 minutes.`, ERROR `Sign-in to <name> failed: <error>`; a server that went to another status without an error, WARNING `Sign-in to <name> ended: the server is now <status>.`; one no longer listed, WARNING `Sign-in to <name> ended: <name> is no longer configured.`), whether the panel is open or not; the panel also shows the caption. The poll lives in the session's scope, not the panel's: a panel reopened while it runs reads `handle.mcpAuth` and shows the wait with its elapsed time and `Cancel` (`manager.cancelMcpAuth(id, name)`); after the outcome it shows the final row.

### 3.4 Slash palette

Typing `/` as the first character of an empty composer (and any draft matching `^/\S*$`: one token, no space yet) opens a popup above the composer box, never over it: polish 3.4's `AboveAnchor(alignEnd = false)` anchored to the box, unchanged, so the popup's bottom sits polish 2.3's 8 dp above the box's top (every composer menu opens above its anchor); as wide as the box (a `PopupPositionProvider` cannot size the popup, so `PromptBox` measures the box with `onSizeChanged` and passes the width to the palette content); its height at most min(8 rows, the space above the box), scrolling past that, never clamped down over the box; `testTag("slash-palette")`. The popup never takes focus and is never dismissed by a click: `androidx.compose.ui.window.Popup(AboveAnchor(alignEnd = false), properties = PopupProperties(focusable = false, dismissOnClickOutside = false))`, so every key still reaches the `TextArea`, the text area and the Send button stay uncovered, and a press outside goes to what it lands on (whether a non-focusable `Popup` under IntelliJ's Compose layers lets that press through is unverified, 11 item 14); a mouse click on a row picks it. The palette closes on Esc, a space, a pick and a draft that stops matching `^/\S*$`, and it shows only while the `TextArea` has focus (`onFocusChanged`), so a click on Send or anywhere else hides it; there is no `onDismissRequest` rule. Whether the Driver's tree shows a raw non-focusable `Popup` is unverified (11 item 14).

Rows: `/<name>` in the editor style, the `argumentHint` after it in `text.info` when non-empty, the description below in the footer size; a scope label at the right as a plain `Text` pill (base 4.2 pill style, not a Jewel `Chip`, which is focusable and a button): `project` from the description's ` (project)` suffix (recorded, `mcp-slash:1`), `user` from a ` (user)` suffix (**unrecorded** in fixtures: the non-fixture `mcp-list` probe only), `plugin` for a name with a `:` namespace (**a guess**: no plugin command is in any fixture, and `plugin-authoring` at `mcp-slash:1` is a built-in), the suffix stripped from the shown text; nothing for built-ins. The descriptions and hints of commands Tandem does not intercept are the CLI's own catalogue text, shown verbatim as data and outside the hard-rule-8 grep of 3.6 (hard rule 8 governs Tandem's own strings; `update-config`, `insights` and `team-onboarding` name the CLI's product in their descriptions, `mcp-slash:1`, and stay as the CLI wrote them). The rows Tandem intercepts (`mcp`, `model`, `permissions`, `mode`) always show Tandem's description (`Manage MCP servers`, `Pick the model`, `Pick the permission mode` for both `permissions` and `mode`) and no hint, because Tandem replaces those commands: the CLI's `mcp`/`model` hints describe text forms that Tandem's panel and picker replace (`mcp-slash:1`).

The list is the initialize response's `commands` (`mcp-slash:1`, 73 entries), minus `init.terminal_slash_commands` (`doctor`, `color`, `focus`, `reload-plugins`, `mcp-slash:4`), minus `__`-prefixed names (`__remote-workflow`, `mcp-slash:1`: internal, "server-launched sessions only"; typed in full it is still sent as text), plus Tandem's own rows (`/mcp`, `/model`, `/permissions`, `/mode`) appended when the catalogue lacks them, deduplicated by name: neither `permissions` nor `mode` is in the 2.1.306 catalogue (`mcp-slash:1`, `:4`), so without the merge `/perm` would list only `fewer-permission-prompts` (a substring match, `mcp-slash:1`), and `/mode` + Enter would pick `model` (`mode` is a prefix of its name) and open the model menu; with the `mode` row the exact name wins. The `mode` row is a deliberate deviation from decision 2's "/mode if present": the catalogue never has it, and the exact row is what keeps `/mode` from opening the model menu. It is filtered by the typed prefix: exact name, then name prefix, then alias prefix (`/rev` lists `code-review` as `/code-review · via /review`), then substring, catalogue order within a rank; an alias is a match key, never a row, and an exact name beats an alias match (probes 2.7, docs: "a marked row wins"): `review` is both a project command and an alias of `code-review` (`mcp-slash:1`), so `/review` lists the project `review` first, then `/code-review · via /review`. Empty catalogue (no initialize answer yet, an older CLI, a stopped session): Tandem's four rows plus the names of `init.slash_commands` when known, and the footer `Commands load when the session starts`. No match: `items` is empty and the footer reads `No matching command`; Enter then sends the draft as typed (`pick`, 4.3).

Keys (`Modifier.onPreviewKeyEvent` on the `TextArea`, through `composerKey` with the new `paletteOpen` argument, pure and tested): Up/Down move the selection (clamped, no wrap); Enter picks the selected row; Tab inserts the selected row's `/<name> ` (always with the space, so the palette closes) without sending, busy or not; Esc closes the palette (the text stays, and the palette stays closed until the draft changes: `ChatUiState.paletteDismissedFor`, 4.4); typing filters; a space, or deleting the `/`, closes it; a mouse click picks. Picking is one pure function, `pick` (4.3, tested in `SlashPaletteTest`), whose `PaletteOutcome` `PromptBar` only executes: a row Tandem intercepts (`mcp`, `model`, `permissions`, `mode`) runs `slashIntercept` at once, whatever the catalogue's hint (`mcp`'s is `[reconnect|enable|disable [<server>|all]]`, `model`'s `<model>`, `mcp-slash:1`); any other row whose hint has a `<…>` placeholder outside every bracketed `[...]` group (the rule is that text test, not the argument's meaning: `compact`'s `<optional custom summarization instructions>` is optional by the CLI's own words, `mcp-slash:1`, and is inserted on purpose so the user can type instructions) puts `/<name> ` in the composer and closes the palette (the user types the argument and presses Enter); a row whose hint is empty or only `[...]` groups (`usage` `""`, `clear` `[name]`) is sent at once as `/<name>`, the row's name and not the typed prefix (`/us` + Enter on `usage` sends `/usage`). Sending runs the interception table on the trimmed text, palette or not (a pasted `/mcp` behaves the same):

| Typed and sent | What happens |
|---|---|
| `/mcp` | opens the panel; the composer is cleared; nothing is sent |
| `/mcp <args>` | sent as text; shows as a notice if the CLI answers locally (the `/mcp reconnect x` forms are unrecorded, 11 item 8) |

Before the first turn the answer is `mcp-status:2` (`pending` ×2) → the controller refreshes again after 2 s. A panel opened before the process is attached shows the stopped state and refreshes once `handle.status` leaves `STOPPED` (3.2). Close → controller cancelled; no request until reopened.
2. **Toggle.** `Disable echo` → caption `Disabling…` → `mcp_toggle {serverName:"echo", enabled:false}` → bare success (`:19`) → the controller's `refresh()` → `refreshMcp` → `:20` `Disabled` → `Enable` offered; the next `init` (`:23`) agrees, drops echo's stale tools and version, and `mcp__echo__echo` leaves `init.tools` (back at `:48`). `Enable` → `:34`/`:35` `Connected`. 3. **Reconnect.** `broken` → `Reconnecting…` → error `Connection closed` (`:36`) shown in the row, status unchanged after the refresh. A reconnect that works (unrecorded) answers a bare success; the refresh shows the new state.
4. **Authenticate, success.** `authy` → 3.3 steps 1–3; the fake flips the server to `connected` once `TANDEM_FAKE_AUTH_DONE_MS` have passed → the poll ends with `Connected` → `Signed in`, the notice `Signed in to authy.`, badge `2/3`.

## 7. Errors and edge cases

- **A CLI that does not know an MCP subtype**: it answers an error (`docs/protocol.md` 4.1 example `Unknown subtype`, unrecorded for these subtypes) or not at all (timeout). For `mcp_authenticate`: `Could not start sign-in: <error>` with the terminal hint (3.3 step 4); for `mcp_toggle`/`mcp_reconnect`: the error in the row; for `mcp_status`: `Could not list servers: <error>` with `Retry` in the title area, the rows staying as the init's thin list (3.2). The report records all four only on 2.1.306 and says nothing about older versions. No version gate: try, then show.
- **Server removed mid-poll** (another client ran `mcp_set_servers` or the config changed): `Removed` → row gone, title note (3.3). **Renamed**: same as removed plus a new row. **Removed before an action**: the action answers `Server not found: <name>` (`mcp-status:38`) and the follow-up refresh no longer lists the name → `<name>: <error> · <name> is no longer configured` in the title area (3.2, 4.4).
- **Two actions at once**: `mcpActions` serialises the requests one `request()` at a time (a toggle's follow-up refresh runs after the lock is released, so nothing deadlocks); the UI disables every other row's buttons while one of the four requests runs, so a second can only come from a test; it then waits. The sign-in waits are not actions: each server's poll (one wait per server, 4.2) takes the mutex per status call, so a `Disable` on another row, or a second server's wait, runs between polls.
- **Session ended** mid-request (exit, `close()`, `stop()`, failed launch): `Reply.Ended` → `McpError.Ended` → `The session has ended.`; the panel keeps the last rows greyed (the controller greys them as soon as `handle.status` is `STOPPED`, 4.4); the polls stop. A session that was never started or has stopped: `NotRunning` → the 3.2 message (during a sign-in poll `NotRunning` means the process is gone and ends the wait as `The session has ended.`, 3.3); the badge shows the last known counts from `ChatState` (not persisted across IDE restarts: a reopened session shows nothing until its first `init`).
- **Panel closed mid-request**: the controller's call is cancelled (not `startMcpAuth`, which runs whole in `handle.scope`, 3.3 step 2), `request()`'s `finally` removes the entry, and the CLI's answer reaches the reducer; an error shows in the chat as `The CLI rejected a request: …` (probes 3.3: "as a notification when the panel is closed").
- **No commands in initialize** (no answer yet, an older CLI, or an empty list; `commands: []` at `mcp-status:1` was emptied by the redactor, probes 1, and is not CLI behaviour, but it drives the same path in the tests): the fallback palette of 3.4. `init.slash_commands` names fill it when known. `terminal_slash_commands` absent → nothing hidden.
- **Request timing out**: 15 s / 30 s (4.2) → `TimedOut(seconds)` → the 3.2 / 3.3 wording with `Retry`; a late answer reaches the reducer and, if an error, the chat as `The CLI rejected a request: …` (never silent).
- **Unknown status text**: an unrecognised `status` maps to `McpStatus.OTHER` with the wire text as the label (`Unknown status` when blank or missing) and the error line when `error` is present; `Disable`* only (3.2). The `/mcp` display states `session token rejected`, `hidden`, `managed` and org-blocked tools (probes 2.5, docs only) may arrive as such a text, or instead as `failed` or `needs-auth` with or without an `error`: unrecorded (11 item 1). A connector that needs `/login` gets no Tandem action beyond the text: the row's error line shows the CLI's `error` verbatim whatever the status (3.2), and Tandem adds no login hint of its own (hard rule 3: signing in to the CLI is the CLI's business).
- **`authUrl` not browsable** (`file:`, a custom scheme, relative): `Could not start sign-in: the sign-in link is not an http(s) URL`; nothing opens (4.1 `browsableUrl`).
- **Names**: config text, drawn as plain `Text`, never parsed; `serverName` sent byte for byte. A connector's display name strips the `claude.ai ` prefix for the row only. A user's server named `tandem` in project or user config is an ordinary row (Tandem's own needs `source == "dynamic"`; 11 item 11).
- **A `pending` that never settles**: five re-polls (10 s), then `Pending` stays with the manual `Refresh servers`.
- **`mcp_status` while a turn runs**: sent (Tandem does not gate requests on `busy`). The CLI answers `interrupt` mid-turn (`interrupt.ndjson:13`, `history-interrupt.ndjson:11`: `{"still_queued":[]}` between a turn's `init` and its `result`), but whether it answers the `mcp_*` subtypes mid-turn is **unrecorded**: every `mcp_status` in `mcp-status` falls between turns (`:2` before turn one's lifecycle starts at `:3`, `:18` after its completion at `:17`, `:34-45` after `:33`), none mid-turn (11 item 13). If the CLI holds those answers until the turn ends, a long turn makes them time out: a refresh keeps the rows and shows `The CLI did not answer within 15 s.` with `Retry` in the title area, a row action shows its timeout in the row with `Retry`, the sign-in poll counts the tick as no change (3.3 step 2), and the late answer still reaches the reducer (4.2). The badge may flicker between the thin list and the detailed answer; both are the CLI's truth.
- **Palette and IME**: the palette filters on the committed text only; a composition in progress does not move the selection (open item 5).
- **Intercepted command with attachments** (polish 2.7): nothing is sent, the draft is cleared, the strip keeps its images for the next prompt.
- **`system/commands_changed`** (probes 2.7, docs only): decodes to `Unknown` and is logged at debug, so the palette's catalogue stays the initialize answer.
- **Local-command text that mentions `/mcp`** but is not the `mcp` command (e.g. the model's own text): untouched; the link rule keys on `runCommand`, not on text.

## 8. Performance

No request while the panel is closed (only a running sign-in poll, at most 3 minutes); one `mcp_status` in flight per session at a time (a refresh asked while one runs waits for one shared follow-up run, SessionManager's per-handle flag). The owner's 41 servers: one answer of a few KB, read on the IO reader thread as every line is, its payload decoded on `Default`, the model built on `Default`, rendered in a `LazyColumn` keyed by name. The badge is a `derivedStateOf` over `mcpServers`, recomposing only on count changes. The palette filters ≤ 100 commands on every keystroke on the EDT (string prefix tests, microseconds; `slashPalette` is pure and allocation-light: one list). Polling: a 2 s period for at most 3 minutes per authenticate, cancelled with the session. The `replies` map holds at most a handful of entries and never leaks one (4.2 `finally`). Nothing here touches the transcript on disk.

### 12.1 What the user sees

- **Typing.** A draft whose first non-blank character is `!` and that has a non-blank command after it (`^\s*!\s*\S`, `chat/ComposerModel.shellCommand`, 12.4) is a shell escape: Enter (or a click on `Send`) runs it instead of sending it; the draft is cleared, the attachment strip (polish 2.7) is left untouched, and the list follows its bottom again (`ScrollEvent.Sent`), as a send does. The command is the text after `!` with its leading and trailing whitespace removed, newlines inside kept (Shift+Enter writes a multi-line command, passed whole to the shell). A bare `!` (nothing but whitespace after it) is not a shell escape and goes to the CLI as text, as today. `!` never opens the slash palette (3.4 needs a leading `/`), and the shell escape is checked before the interception table of 3.4 and before polish 4's attachment encoding. The placeholder stays `Type / for commands` (3.6).
- **The row** (`ShellRow`, 12.4; `ui/rows/ShellRowItem.kt`), in place of a user bubble, at the turn's position: a header line in the editor style, `text.normal`, reading `! <command>` (the form of the CLI's own `last-prompt`, `transcripts/bash-mode-interactive.jsonl:15`), wrapping, every line of a multi-line command shown; at its right, while the command runs, an `IconButton` `Stop command` (`AllIconsKeys.Actions.Suspend`, as the composer's Stop). Under the header, once there is output, the output, drawn as polish 2.4 item 3 draws a Bash body's output: mono, no fill and no box, in the secondary tier, 10 dp below the header (decided here: polish 2.4's unframed form, not a filled `MonoBox`, so a shell row's output reads like a Bash call's), with colour escapes stripped (`ToolLabels.stripAnsi`, as `ToolBodies` does for Bash output; the frames keep the raw text), live while the command runs (each batch of output appends), clamped at 20 lines with `Show more` / `Show less` exactly as a tool body (polish 2.2, `Clamped(row.key, "output", …)`, so the clamp state is keyed `sh:<id>`); no output block while the output is empty (a command that printed nothing, a reloaded one whose output was empty). Under the box (or the header) a status line in the footer size when there is something to say: `exit N` in `text.error` for a non-zero exit code; `Stopped after <elapsed>` (`formatDuration`, `chat/Text.kt`) in `text.error` when Stop or the session's close ended it; `Killed after 10 minutes` in `text.error` at the cap; `Could not start <shell>: <reason>` in `text.error` when the shell did not launch (`<shell>` is the argv's first element, `/bin/zsh`; `<reason>` the OS error text, `No such file or directory` for a missing shell, 12.4); `Could not read the command's output: <reason>` in `text.error` when reading the output failed (12.6). Nothing for exit 0 and nothing for a reloaded row (the transcript keeps no exit code, bash probes 2.1).
- **Then Claude answers**, with the setting on: the row stays, the working row shows under it while the CLI thinks, the reply and its `Worked for` footer follow, exactly as after a prompt (`bash-mode-respond.ndjson:10-41`). With the setting off: nothing follows; the next prompt's reply knows the output (`bash-mode.ndjson:18-19`, the model repeats `bash-mode-probe`). Either way the CLI echoes nothing (bash probes 3): the row and its output come only from Tandem's own run, so the zero-turn `result` of the quiet send (`num_turns: 0`, `result: ""`, `bash-mode.ndjson:8`, `bash-mode-respond.ndjson:6`) draws no footer, no working row, no notice and raises no attention.
- **Composer while it runs.** The composer is busy as during a turn: the Send button becomes Stop, Enter does nothing (`composerFallback` swallows it), Esc stops the command (12.3). `Stop` in the composer and `Stop command` on the row do the same. A second `!` line cannot be typed into a run (Enter is swallowed), so at most one command runs per session.
- **Reload.** A transcript's `<bash-input>` line and its `<bash-stdout>…</bash-stdout><bash-stderr>…</bash-stderr>` line, on one line (`transcripts/bash-mode.jsonl:5`, the merged form with `\n` between the two tags) or on two (`transcripts/bash-mode-respond.jsonl:3,6`; `transcripts/bash-mode-interactive.jsonl:5,6`), load as one `ChatEntry.Shell` with the command and the output (`SessionEvent.ShellLoaded`, then `ShellOutput` for a separate output line, 12.4), drawn as the live row was, minus Stop and the status line (a non-empty `<bash-stderr>` shows after the stdout text on a line of its own, `BashLine.shown`, 12.4; a stopped or capped command's note, sent as the last line of `<bash-stdout>`, reloads as the output's last line) (11.4's table changes: `<bash-stdout>`, `<bash-stderr>` are shown as the row's output, no longer skipped). An output line with no shell entry before it to belong to (the stray `<bash-stderr>` line of the existing reader test) stays skipped. // session/ShellRunner.kt (JDK + kotlinx.coroutines only)
fun interface ShellLauncher { fun launch(argv: List<String>, directory: Path, environment: Map<String, String>): Process }
object Shells {
    fun argv(command: String, environment: Map<String, String>, os: String = System.getProperty("os.name")): List<String>
    //   Windows (os contains "windows", ignoring case): [environment["ComSpec"] ?: "cmd.exe", "/c", command] (unverified, 12.6);
    //   else [environment["SHELL"]?.takeIf { it.isNotBlank() } ?: (if (os.startsWith("Mac")) "/bin/zsh" else "/bin/sh"), "-lc", command]
    //   (the owner's /bin/zsh when SHELL is missing on macOS, whose default shell it is; /bin/sh elsewhere): a non-interactive login shell: the login profile's PATH and exports
    //   (.zprofile/.zlogin, .bash_profile/.profile) reach the command; aliases and functions from .zshrc/.bashrc do not (no interactive shell;
    //   -i without a TTY prints job-control warnings), 12.6, 12.9 item 6
    const val MAX_OUTPUT_CHARS: Int = 100_000       // kept in memory and sent; the rest is drained and counted
    const val TIMEOUT_MILLIS: Long = 600_000         // the 10-minute cap
    const val BATCH_MILLIS: Long = 50                // output reaches the reducer at most this often
    fun defaultLauncher(): ShellLauncher             // ProcessBuilder(argv).directory(directory).redirectErrorStream(true), environment replaced by [environment]; start()
}
sealed interface ShellEnd {
    data class Exited(val code: Int) : ShellEnd; data object Stopped : ShellEnd; data object TimedOut : ShellEnd; data class NotStarted(val shell: String, val reason: String) : ShellEnd
    data class Failed(val reason: String) : ShellEnd   // reading the output threw (12.6); set by the manager, never by the runner
}
data class ShellResult(val output: String, val end: ShellEnd, val durationMs: Long, val cut: Int)   // cut: characters dropped past MAX_OUTPUT_CHARS; output then ends with "\n… (cut, <cut> more characters)"
class ShellRunner(launcher: ShellLauncher = Shells.defaultLauncher(), environment: () -> Map<String, String>, clock: () -> Long = System::currentTimeMillis,
                  timeoutMillis: Long = Shells.TIMEOUT_MILLIS, batchMillis: Long = Shells.BATCH_MILLIS) {
    suspend fun run(command: String, directory: Path, onOutput: suspend (String) -> Unit): ShellResult
    //   on Dispatchers.IO: argv = Shells.argv(command, environment()), the process's stdin closed right after start (a command that reads it sees
    //   EOF); stderr merged in order by redirectErrorStream (as the 2.1.306 TUI merges it, bash probes 2.1). The read loop polls, as
    //   ide/ClaudeBinary.outputOf does ("a read blocked on a pipe could be neither cancelled nor woken by closing the stream"): each pass notes
    //   exited = !p.isAlive first, then reads only what p.inputStream.available() reports, at most 8 KB at a time, then yield(); when nothing is
    //   available it returns if exited, else delay(15 ms). It never makes a blocking read, so withTimeoutOrNull, Stop and close() act at once
    //   (`sleep 60` included), and it returns once the shell has exited and the pipe holds nothing, so a backgrounded child that keeps stdout
    //   open (`! npm run dev &`) cannot hold the row (the child itself then loses the pipe and dies on its next write, 12.6). Bytes decode as UTF-8 with U+FFFD for a malformed byte (a CharsetDecoder over the polled
    //   chunks, so a sequence split across chunks is not broken), batched to onOutput every batchMillis or 8 KB, whichever first;
    //   withTimeoutOrNull(timeoutMillis) around the loop → TimedOut, the tree killed; the caller's cancellation → the tree killed in a finally
    //   (descendants().forEach(destroyForcibly), then destroyForcibly), then rethrown (the manager records Stopped); the process is in `running`
    //   (a concurrent set) from start to that finally. A launch that throws → NotStarted(argv[0], reason), nothing read, where reason =

### 12.5 Flows

1. **`! echo hi`, replies on.** Enter → `shellCommand` → `manager.runShell` → `ShellStarted` → the row `! echo hi` with `Stop command`, the composer busy → `/bin/zsh -lc 'echo hi'` in the project directory → `ShellOutput("hi\n")` → the box shows `hi` → `ShellEnded(Exited(0), 12 ms)` → Stop gone, no status → `respondToShell()` true → `ShellSent(quiet = [u1], query = u2)` → busy, working row → frame `bashInput("echo hi", u1)` → the CLI: lifecycle, `init`, zero-turn `result` naming `u1` (`bash-mode-respond:3-7`; quiet: no footer, the turn stays open) → `u1` leaves `quietSends` → frame `bashOutput("hi\n", "", u2, query = true)` (the recorded order, never back to back, 12.4) → lifecycle, `init`, `status requesting`, thinking, text (`:8-36`), `result` naming `u2` (`:41`) → `TurnEnded`, `Worked for` footer, the reply under the row.
2. **Replies off.** As 1 until the end, then one frame `bashContext("echo hi", "hi\n", "", u)` (recorded: `bash-mode-context:3-6`, 2.1.308) with `ShellSent(quiet = [u], query = null)` → zero-turn `result` naming `u` (`bash-mode-context:6`) → nothing drawn, the composer free; the next prompt's reply reads the output (`bash-mode-context:7-20`).
3. **Stop.** `! sleep 60` → Stop (row, composer or Esc) → `stopShell` → the job cancelled → the tree killed → `ShellEnded(Stopped, 3 s)` → status `Stopped after 3.0s` → frames whose `<bash-stdout>` holds the output so far and then `Stopped after 3.0s` on a line of its own, `<bash-stderr>` empty → Claude answers (or not, per the setting).
4. **Cap.** No end after 10 minutes → killed → `Killed after 10 minutes` in the row and as the last line of `<bash-stdout>`.
5. **Could not start.** `SHELL` points nowhere → `NotStarted` → `Could not start /opt/none/zsh: No such file or directory` under the header (the reason cut from the JDK's `error=2, No such file or directory` or `Exec failed, error: 2 (No such file or directory)`, 12.4); no frame; the composer free.
6. **Reload.** The session reopened: `transcripts/bash-mode.jsonl:5` → `Shell("echo bash-mode-probe && printf err >&2", "bash-mode-probe\nerr")` → the row with its box, no Stop, no status; `:8` the prompt, its reply; the same from `bash-mode-respond.jsonl:3` + `:6` and `bash-mode-interactive.jsonl:5` + `:6`.
7. **Stopped session.** A session whose process has ended: `! ls` runs at once (Tandem's own process); the frames are queued (`Outbound.ShellEscape`) and a process starts for them, as a prompt starts one (`SessionManager.send`); the row shows meanwhile.

### 12.6 Errors and edge cases

- **The session ends while the command runs.** The CLI's process exits (`Ended`): the command runs on in `handle.scope`; at its end the frames queue and start a process (flow 7). The session is closed or deleted (`handle.close()`): the scope's cancellation kills the tree, the entry ends `Stopped`, nothing is sent (`handle.isClosed`). The project closes (the handle's parent scope cancelled without `close()`): the same, nothing is sent (`!handle.scope.isActive`). Since the runner never blocks in a read (12.4), the kill and `close()` act at once even for a command that prints nothing (`sleep 60`). The IDE exits: `killAllNow` → `ShellRunner.killAllNow` destroys every running tree without waiting, so no `sleep` outlives the IDE.
- **An escape held behind a prompt when its process ends or is stopped** (a crash, the session's Stop): dropped, as 12.4 says, and since its output never reached the CLI the chat says so with a warning notice after the prompt's turn end, `The output of ! <command's first line> was not sent: the CLI ended first.` (hard rule 5; added in M7a's review). The notice goes in with the process's `Ended`, in one state update, so the handle never takes an ended chat without it; an escape handed to a process that is over but whose chat does not show it yet sends nothing and gets the same notice. An output frame still waiting for its quiet result: when the process ends by itself it needs none, since the turn its escape opened ends with the process (`FAILED`); on the session's Stop, whose settled chat ends that turn without a word, it gets the same notice.
- **Output over 20 lines** clamps like a tool body: 20 lines, a faded bottom, `Show more` (then `Show less`); `ChatUiState`'s clamp state keyed by the row key `sh:<id>` (`clampOpen(row.key, "output")`), so a reopened row clamps again (polish 2.2). Over 400 lines or 50,000 characters the row shows `ToolBodies`' cut (`… (cut, N more characters)`) while the entry keeps up to `MAX_OUTPUT_CHARS`; over 100,000 characters the runner drops the rest, drains the pipe (the process never blocks on a full pipe) and ends the output with `… (cut, N more characters)`, which the frames carry too (what the TUI sends for a long output is **unrecorded**, bash probes open question 2).
- **Reading the output fails** (an `IOException` on the pipe, a decoder bug): the runner's `finally` kills the tree, the manager ends the entry `Failed(reason)`, the row shows `Could not read the command's output: <reason>`, no frame goes out and the composer is free (hard rule 5: never a row stuck running).
- **A backgrounded child** (`! npm run dev &`, `sleep 30 & echo x`): the shell exits at once; the runner returns once the shell has exited and nothing is available, so the row ends `Exited(0)` at once with what was printed. The child does not run on as after a terminal's `&`: when the shell exits, the JDK's process reaper drains and closes the output pipe (`ProcessPipeInputStream.processExited`), so a child that writes again gets `SIGPIPE`/`EPIPE`, and `! npm run dev &` dies on its next log line. A child keeps running only if it redirects its own output (`! nohup npm run dev > dev.log 2>&1 &`); Stop cannot reach it once the row has ended (it is no longer among the shell's descendants).
- **Aliases and functions** (`! ll`): the shell is a non-interactive login shell (12.4), so aliases and functions from `.zshrc`/`.bashrc` are not defined and the command ends with the shell's own `command not found` (`exit 127`); the profile's PATH and exports do reach it (12.9 item 6).
- **The live-session cap and `stopIfIdle`**: a session is not idle while its command runs or a quiet send waits for its result (12.4), so the cap never stops the CLI between a frame and its result. A process that ends or is stopped before a quiet result (a crash, Stop, a respawn) leaves no quiet send behind (`reduceEnded` and `settled()` clear `quietSends`), so the session's next process is idle again; a CLI that omits `user_message_uuids` ends a quiet send through its zero-turn result (12.4's Result rule), with no footer, no attention and no IDE notification.
- **A command that reads stdin** (`cat`, `read x`, `ssh` asking a password): stdin is closed at start, so it sees EOF and ends; an interactive program that needs a TTY (`vim`, `top`, `sudo` asking a password) gets none, prints its error or waits until Stop or the cap (2, non-goals: no PTY).
- **Non-UTF-8 output** decodes with U+FFFD per malformed byte, never throws; the frames carry the replaced text. CRLF output stays as written (the row splits on `\n`, as `ToolBodies` does).
- **Windows**: `Shells.argv` runs `%ComSpec% /c <command>` (no login flag); the row and the frames are the same. **Unverified**: no Windows CI (CLAUDE.md names Linux and macOS runners); `ShellRunnerTest` runs its process tests under `assumeTrue(!isWindows)`.
- **`!` typed with attachments** (polish 2.7): the command runs, the draft clears, the strip keeps its images for the next prompt, as an intercepted slash command does (3.4); the frames carry no image block.
- **`!` while a turn runs**: Enter is swallowed as for any prompt (base 4.15); the terminal's behaviour for a shell escape mid-turn is **unrecorded** (bash probes open question 2). **`!` while a command runs**: swallowed too (the composer is busy). **`!` while the process starts** (`STOPPED` → `IDLE`): the command runs at once; its frames wait in the queue behind any prompt already queued and, once flushed, `sendShellEscape` holds them until that prompt's result (12.4): a prompt and a quiet frame written together would be batched into one send by the CLI (`bash-mode:3-6`), an unrecorded shape.
- **The output contains `</bash-stdout>`**: sent verbatim (the tags are text to the CLI, bash probes 3); on reload `BashEscape.parse` cuts at the last closing tag, so the row shows the whole output.
- **A merge of a quiet and a querying send** (**unrecorded**): the CLI batches the sends queued before it starts processing and merges them into one line (`bash-mode:3-6`, `transcripts/bash-mode.jsonl:5`); whether a merged quiet + querying batch still calls the model is unrecorded, and if it did not, Claude would never answer. So Tandem never writes a shell escape's frames together, nor an escape right behind a prompt (a prompt right behind a quiet frame is 12.9 item 7): the respond frame waits for frame 1's zero-turn result, as `bash-mode-respond` did (`:6`), and a flushed escape waits for the prompt before it (12.4). Should a result still name a quiet uuid beside a querying one (the 5 s fallback, a future CLI), the reducer drops the quiet one and ends the turn as today; the transcript then holds the merged form of `bash-mode.jsonl:5`, which the reader already reads.
- **The quiet `init`**: every `system/init` still runs `checkModel` (hard rule 5) and takes `cwd` and the permission mode; `bash-mode:7`'s `init` carries the same model as `:13`'s.
- **The CLI's own `respondToBashCommands`**: not read (`docs/protocol.md` 11.5: Tandem reads no settings file); the Tandem setting is the only switch, and a user who set the CLI's to `false` gets a reply from Tandem's sends unless they turn Tandem's off (non-goals).
- **A command that prints nothing**: no output block; the frames carry an empty `<bash-stdout></bash-stdout>`.
- **The `!` line is the first prompt**: the title is `! <command>`'s first line (12.1), live (the handle's cache, 12.4) and indexed.
- **A reloaded shell escape followed by a live `!`**: ids are `shell-<n>` from the manager's own counter (`nextShell`), distinct from the loaded entries' line uuids, as notices are.

### 12.7 Performance

The runner polls on `Dispatchers.IO` (what `available()` reports, at most 8 KB a read; a 15 ms `delay` while the pipe is empty, so a quiet command costs about 65 wake-ups a second and blocks no thread) and hands the reducer at most one `ShellOutput` per 50 ms (or per 8 KB): a `yes`-style command costs about 20 state updates a second, each a string append on the last entry, and `ChatRowsBuilder` rebuilds only the last turn (the shell row's cut is O(100,000) characters at worst). The output recomposes per batch with at most 20 lines drawn while clamped. Nothing runs on the EDT: `shellCommand` is a regex on the draft; `runShell` and `stopShell` only launch or cancel. The frames are at most 100 KB + tags, one `send` each. A stopped command's tree is killed in a `finally` on IO; `killAllNow` is synchronous and never waits.
