# Windows Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tandem runs on Windows with the CLI installed by npm (`%APPDATA%\npm\claude.cmd`, which calls `node_modules\@anthropic-ai\claude-code\bin\claude.exe`) or by the native installer (`%USERPROFILE%\.local\bin\claude.exe`); the unit, fixture and platform tests are green on `windows-latest` for every pull request that changes what Gradle reads, and the IDE test runs there nightly and on demand.

**Architecture:** the test bed first (the fake CLI's Windows mode, `fake-claude.cmd`, `.gitattributes`, the probe workflow running the whole suite and failing on red), then the test helpers that drop every `sh -c`, then the product code a first session hits (`ClaudeBinary` finding and resolving the shims, `PATHEXT`, the drive-root refusal, the `! command` shell in Git Bash), then CI (`build-windows`, `windows-ide-test.yml`) and the docs. There is no Windows machine: every task is proved by the `Windows probe` run that each push to `feat/windows` starts, read through the GitHub MCP tools.

**Tech Stack:** Kotlin, IntelliJ Platform (JUnit 5 unit and platform tests, IDE Starter), Gradle, the Python fake CLI (`src/test/resources/fake-claude.py`, standard library only), GitHub Actions (`windows-latest`).

**Spec:** `docs/superpowers/specs/2026-11-08-windows-support-design.md` (findings R1 to R17 in section 3, the probe's results in 4.1, the fake's Windows mode in 5, CI in 6, the `CLAUDE.md` section in 7, the slices and tiers in 8, the tester questions in 9).

## Global Constraints

- Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better.
- CLAUDE.md hard rules, verbatim:
  1. **Never block the EDT.** No process I/O, file I/O, JSON parsing or waiting on the CLI from the UI thread. Use the platform coroutine scopes (`platform-coroutines-structured-concurrency` skill).
  2. **No Node, no Agent SDK at runtime.** We spawn the user's `claude` binary directly. Do not add a sidecar.
  3. **Never touch credentials.** Auth belongs to the CLI. Do not read `~/.claude/.credentials*`, keychains or API keys, and never offer a login flow.
  4. **Edits go through the IDE, not the disk.** Claude's built-in Edit/Write tools are disabled; our MCP edit tools apply changes with `WriteCommandAction` on the `Document`, so undo, unsaved buffers and local history work. Every edit shows a native diff before it lands, unless the user picked auto-accept.
  5. **Never fail silently.** If the CLI falls back to another model, rejects a model, retries, or errors, the user sees it in the chat. Compare the model in the `system/init` event (and fallback events) with what the user picked.
  6. **Every protocol change gets a fixture test.** Recorded transcripts live in `src/test/resources/fixtures/`. Unknown message types must parse to `Unknown(raw)`, never throw. `synthetic-long-reply.ndjson` is generated by `scripts/make_long_reply.py` and is the only unrecorded fixture.
  7. **Do not bundle kotlinx.coroutines or the Kotlin stdlib.** The platform provides both.
  8. **Do not call the product "Claude Code"**, in the plugin name, ID or UI. Use "Tandem" and say it works with Claude Code.
- Scope (spec 2.2), verbatim where it matters: no WSL; no Remote Development; no PowerShell as the `! command` shell (`! command` follows the CLI: Git Bash, else `cmd.exe` with a note); the CLI's Windows sign-in is the CLI's business; the README's status line ("macOS and Linux today; Windows in progress") and its `README.zh-CN.md`, `README.ja.md`, `README.ko.md` twins stay unchanged until a real user has run Tandem on Windows and said so (the owner changes it, never a task here).
- Layers (CLAUDE.md Layout): `session/` imports only the JDK, kotlinx.coroutines, kotlinx.serialization.json, kotlinx.collections.immutable and `com.intellij.openapi.diagnostic`; `chat/` no IntelliJ at all; platform facts (`SystemInfo.isWindows`) enter `session/` only as parameters with defaults from `System.getProperty("os.name")`, as `Shells.argv` does today.
- Conventions: Kotlin with explicit types on public API; validate everything from the CLI; never log a command, a path's contents or a secret; Conventional Commits; `koverVerify` needs 90 % of lines in each package of `protocol/`, `session/` and `chat/`, so new branches in `session/ShellRunner.kt` come with pure tests.
- Where the work happens: the worktree `/home/user/tandem-win` on the branch `feat/windows`, which already holds the spec and `.github/workflows/windows-probe.yml`. Scratch files under `scratch/` (gitignored). Never on `main`.
- Gradle: every command carries `--init-script scratch/central-mirror.init.gradle.kts`; never two Gradle commands at once in the tree. One class: `./gradlew test --init-script scratch/central-mirror.init.gradle.kts --tests 'dev.daarkolabs.tandem.<pkg>.<Class>'` (written `GRADLE test --tests …` below); the suite with coverage: `./gradlew check --init-script scratch/central-mirror.init.gradle.kts` (written `GRADLE check`). The script tests: `cd scripts && python3 -m unittest -v`.
- Commits: staged by path, no trailers, no AI attribution: `git -c user.name="Dago Kogos" -c user.email="34120174+daarko10@users.noreply.github.com" commit --author="Dago Kogos <34120174+daarko10@users.noreply.github.com>" -m "<type>: <subject>"` (written `COMMIT -m …` below), then `git push origin feat/windows`.
- **The Windows signal (every task's verification).** There is no Windows machine. The implementer runs the Linux tests locally, commits, pushes, and the workflow `Windows probe` (`.github/workflows/windows-probe.yml`, `push: branches: [feat/windows]`) runs the whole `gradlew.bat test` on `windows-latest` from Task 1 on. - Deviations from the spec (decisions, not contract breaks):
  1. **The Git Bash note travels as the output's first line.** Spec R6 wants the row's first line to say `Ran in cmd.exe: Git Bash was not found`.   7. **R14's list is widened** to every `#!/bin/sh` and `sh -c` site: `TandemSettingsTest.kt:60,90` and `ClaudeBinaryTest`'s `PATH order wins…` / `nothing found…` (a `PATH` joined with `:`) are fixed in Task 2 too.
