# IDE-Native Edits Implementation Plan: Tandem's Edit Tools over the Control Channel, the Editable Diff, Mentions and the Selection

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude changes files through the IDE: `edit_file` and `write_file` are Tandem's own tools, served to the CLI as the SDK MCP server `tandem` over the control channel it already has (`initialize.sdkMcpServers`, `mcp_message` requests), with the built-in `Edit`, `Write`, `MultiEdit` and `NotebookEdit` kept disallowed. Every call opens the platform's diff with the file's own `Document` read-only on the left and the proposal **editable** on the right; Accept (Ctrl+S, ⌘S; Ctrl+Enter, ⌘↵) applies the right side with one `WriteCommandAction`, saves the document to disk and answers the CLI with **the file as it now is** (the owner's words: "when I click save it will send the latest version of the file to the llm as a result cause programmers might change what it put out small changes by hand which is the strength of the diff viewer in jetbrains"); Reject answers an error with the typed reason; `acceptEdits`, `bypassPermissions` and `Accept all` apply without a diff; Stop withdraws the call. `@` in the composer opens a file picker that inserts the CLI's own `@path` mention (a dirty buffer is sent as a text block instead), and the editor's selection travels with the prompt as a removable chip.

**Architecture:** the foundation lands first, in order: F1 records the four scenarios with the real CLI and teaches the redactor the new key; F2 types the frames in `protocol/` (`InboundRequest.McpMessage`, `HostMessages.mcpResponse`, `initialize`'s `sdkMcpServers`, `userMessage`'s context blocks, `TandemTools`); F3 gives `session/` the interfaces both lanes build on (`HostTools`, the routing and cancellation in `ClaudeSession`, the auto-allow, the version gate, `ChatState.edits` / `acceptAll` / `ContextChip`, `nonExecutionKind` on a result, the MCP panel's refusal). Then two lanes run side by side in two worktrees: lane A is the edit itself (A1 the pure matcher and result texts, A2 `IdeEditTools` on the `Document`, A3 the diff, the queue and `TandemEdits`, A4 the chat rows and the panel, A5 the fake CLI's `mcp_message` branch and the six IDE tests); lane B is context (B1 the `@` palette, the dirty-buffer swap, the bubble chips and the reload, B2 the selection chip). After the merge, X1 writes the docs and the claims and X2 bumps the version to 0.4.0 and runs every suite; the whole-branch review on Fable follows.

## Global Constraints

- Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better.
- CLAUDE.md hard rules, verbatim:
  1. **Never block the EDT.** No process I/O, file I/O, JSON parsing or waiting on the CLI from the UI thread. Use the platform coroutine scopes (`platform-coroutines-structured-concurrency` skill).
  2. **No Node, no Agent SDK at runtime.** We spawn the user's `claude` binary directly. Do not add a sidecar.
  3. **Never touch credentials.** Auth belongs to the CLI. Do not read `~/.claude/.credentials*`, keychains or API keys, and never offer a login flow.
  4. **Edits go through the IDE, not the disk.** Claude's built-in Edit/Write tools are disabled; our MCP edit tools apply changes with `WriteCommandAction` on the `Document`, so undo, unsaved buffers and local history work. Every edit shows a native diff before it lands, unless the user picked auto-accept.
  5. **Never fail silently.** If the CLI falls back to another model, rejects a model, retries, or errors, the user sees it in the chat. Compare the model in the `system/init` event (and fallback events) with what the user picked.
  6. **Every protocol change gets a fixture test.** Recorded transcripts live in `src/test/resources/fixtures/`. Unknown message types must parse to `Unknown(raw)`, never throw. `synthetic-long-reply.ndjson` is generated by `scripts/make_long_reply.py` and is the only unrecorded fixture.
  7. **Do not bundle kotlinx.coroutines or the Kotlin stdlib.** The platform provides both.
  8. **Do not call the product "Claude Code"**, in the plugin name, ID or UI. Use "Tandem" and say it works with Claude Code.

## Review Focus

1. The disk holds the applied text, and `isDocumentUnsaved` is false, **before** the `mcp_response` goes out, or the model's next `Read`/`Bash` sees the pre-edit file while the result says it landed → A2 `IdeEditToolsTest` `the disk holds the applied text when the reply is sent`; A5 IDE test `an edit opens the diff and Accept applies it` (the disk polled, then the log line's position after it).
2. A hand change on the right side is what lands and what the model is told: never the original proposal, never a stale left side → A3 `EditDiffTest` `typing into the right document and Accept resolves Accepted with the changed text`; A2 `the file changes while the diff is open, changed proposal` (no `setText` on a document that differs from `original`); A5 IDE test `a hand change in the diff reaches Claude`.
3. Closing the diff without a choice is a rejection, a viewer switch is not → A3 `EditDiffTest` `closing the tab rejects`, `switching the viewer does not reject` (the reviewer reads `EditDiff` for `Disposer.register(editors[0], …)` plus `fileClosed`, and for no use of `onAssigned`).
4. Ctrl+S inside the diff is Accept and never the IDE's Save All; outside the diff Save All is untouched → A3 `the Accept action carries the SaveAll shortcut set and is registered on the file editor's component`; the owner's `runIde` pass (spec 9.8).
5. Nothing hangs the CLI: every `mcp_message` gets exactly one reply, except a withdrawn call, which gets none → F2 `RobustnessTest` (`-32600`, `-32601`, string ids), F3 `ClaudeSessionTest` `notifications/cancelled cancels the pending call's job and the late reply is not sent`, `an unknown server_name gets -32601`; A5 IDE test `Stop closes the diff` (no `mcp_response` for the call in the log).
6. A Tandem tool's `can_use_tool` never shows a permission card and the rejected row is `DENIED`, the stopped row `INTERRUPTED`, never `FAILED` → F3 `a can_use_tool for mcp__tandem__edit_file is answered allow with the input and raises no pendingPermissions`, `a user-rejected result without a decision keeps its kind`; A4 `ToolStatesTest` `a rejected edit is DENIED despite the accept decision`, `a user-rejected result is INTERRUPTED`.
7. The MCP panel never offers to disable Tandem's own server, whatever source the CLI reports → A4 `McpPanelModelTest` `Tandem's own server with source sdk is read-only`; F3 `McpControlsTest` refusal cases.
8. `Accept all` is per session and per turn, and the checks (roots, binary, size, plan mode) never widen under it → A3 `TandemEditsTest` `Accept all applies the next call of the same turn without a diff and ends at the result, and the next turn's call opens a diff again`; A2 `plan mode refuses`; A5 IDE test `Accept all skips the next diffs`.
9. The model never sees the selection or a buffer by accident: no chip, no block; a context-only message is refused → B2 `ComposerSenderTest` `no block goes out without the chip`; B1 `a context-only message is refused as an empty draft`.
10. The mention palette never steals Enter from a plain send and `@` inside a word opens nothing → B1 `MentionPaletteTest` `@ inside a word does not open`, `ComposerKeysTest` `Enter with the palette closed sends`.
