# Tandem

A fast, native JetBrains plugin for Claude Code. Free and open source.
It drives the user's own installed `claude` CLI over stream-json and renders everything with Jewel (Compose).
Read `docs/design.md` before any non-trivial change, and `docs/protocol.md` before touching `protocol/` or `session/`.
Read `docs/launch.md` before any work described as ship, release, publish, launch, announce, post, demo or benchmark, before editing `docs/protocol.md` or the fixtures, and before changing a claim in `README.md` or `plugin.xml`.

## Hard rules (do not break these)
1. **Never block the EDT.** No process I/O, file I/O, JSON parsing or waiting on the CLI from the UI thread. Use the platform coroutine scopes (`platform-coroutines-structured-concurrency` skill).
2. **No Node, no Agent SDK at runtime.** We spawn the user's `claude` binary directly. Do not add a sidecar.
3. **Never touch credentials.** Auth belongs to the CLI. Do not read `~/.claude/.credentials*`, keychains or API keys, and never offer a login flow.
4. **Edits go through the IDE, not the disk.** Claude's built-in Edit/Write tools are disabled; our MCP edit tools apply changes with `WriteCommandAction` on the `Document`, so undo, unsaved buffers and local history work. Every edit shows a native diff before it lands, unless the user picked auto-accept.
5. **Never fail silently.** If the CLI falls back to another model, rejects a model, retries, or errors, the user sees it in the chat. Compare the model in the `system/init` event (and fallback events) with what the user picked.
6. **Every protocol change gets a fixture test.** Recorded transcripts live in `src/test/resources/fixtures/`. Unknown message types must parse to `Unknown(raw)`, never throw. `synthetic-long-reply.ndjson` is generated by `scripts/make_long_reply.py` and is the only unrecorded fixture.
7. **Do not bundle kotlinx.coroutines or the Kotlin stdlib.** The platform provides both.
8. **Do not call the product "Claude Code"**, in the plugin name, ID or UI. Use "Tandem" and say it works with Claude Code.

## Layout
- `protocol/` pure Kotlin: NDJSON codec, typed messages, control requests, and `TandemTools`, the answers of Tandem's own SDK MCP server (`mcp_message`). No IntelliJ imports, so it unit-tests fast.
- `session/` `SessionManager` owns the project's sessions (`SessionHandle`), each with one `ClaudeSession` per live process: spawns the CLI, owns stdin/stdout, reconciles partial and complete messages, exposes `StateFlow`s. `McpControls` is the MCP panel's view of it (list, toggle, reconnect, sign-in); `ShellRunner` runs a `! command` locally. `HostTools` is what the project's edit service implements to answer the CLI's `tools/call`; `session/edits/` holds the pure edit matcher and the result texts. Imports only the JDK, kotlinx.coroutines, kotlinx.serialization.json, the platform's kotlinx.collections.immutable and `com.intellij.openapi.diagnostic`.
- `session/transcript/` the CLI's own transcripts, `<config>/projects/<key>/<id>.jsonl` (`docs/protocol.md` 11): folder key, index, reader. Read-only, except a rename's `custom-title` line and delete.
- `chat/` pure Kotlin presentation of a `ChatState`: the row model (`ChatRowsBuilder`, tool labels, states and bodies), the footer menus' models (`Modes`, `ComposerModel`, `ContextFormat`), `ShellTokens` for Bash bodies, `Attachments`' image checks, the MCP panel's rows (`McpPanelModel`), the `/` palette's list and picking (`SlashPalette`), the context popover's, the `/usage` card's and the `+` menu's models (`ContextBreakdownModel`, `UsageCardModel`, `PluginMenu` by source, `ConnectorMenu`), the queued messages' pending states (`QueuedSends`), the tool window's session tabs (`SessionTabs`), the `@` file palette's list, picking and insertion (`MentionPalette`) and the edit rows' review phases (`ChatRowsBuilder` over `ChatState.edits`).
  Imports only the JDK, kotlinx.collections.immutable, kotlinx.serialization.json and `session/`/`protocol/` types: no Compose, no Jewel, no IntelliJ.
- `ide/` IDE-side integration: the `TandemSessions` project service, the settings page (Settings | Tools | Tandem: `claude` path, max live sessions, show thinking rows, `Claude replies to ! command output`, reduce motion), workspace state, notifications. `ide/edits/` is Tandem's edit tools in the IDE: `IdeEditTools` (path and file checks, then the write command on the `Document` and the save to disk), `EditDiff` (the editable diff with Accept, Accept all and Reject), `EditQueue` (one diff at a time) and `TandemEdits`, the project service that joins them and is the sessions' `HostTools`. `ide/context/` is `ProjectFiles` (the `@` palette's candidates) and `EditorSelection` (the selection chip's source).
- `ui/` Jewel tool window. Renders state from `session/`; holds no protocol logic. Includes `FooterControls` (mode, model and effort menus, the context ring),
  the composer's attachment strip, the hover action row under a reply (`rows/MessageActionsRow`), the question card's Next flow, the MCP panel (`McpSheet`, driven by
  `McpPanelController`), the slash palette (`SlashPaletteView`), the `! command` row (`rows/ShellRowItem`), the context popover on `ContextBreakdownController` and the `/usage` card, the paged `+` menu (`PagedMenu`, with Add folder and its pills, and the Connectors page on the MCP panel's `McpPanelController`), the queued bubbles (`QueuedRow`: a message sent while Claude works, with Edit and Cancel), the session tabs on the tool window's own content manager (`SessionTabsController`, one shared Compose panel under every tab), the `@` palette (`MentionPaletteView`), the selection chip in the composer (`PromptBar`), the selection and unsaved-file chips in the bubble (`UserBubble`), the edit rows' `Show diff` (`rows/EditRowActions`) and the footer's `Accepting all edits this turn` hint, and the actions `Tandem.CyclePermissionMode` (`CyclePermissionModeAction`, Shift+Tab in the composer), `Tandem.AddFilesOrPhotos` (Ctrl+Alt+Shift+O, ⌘⌥⇧O) and `Tandem.NewSession`.

## Commands
- `./gradlew test` unit, fixture and headless platform tests (no real `claude`; a fake CLI replays fixtures).
- `./gradlew koverLog` line coverage of `protocol/`, `session/` and `chat/` per package after the tests (Kover, build-time only); `koverHtmlReport` writes `build/reports/kover/html/`. `./gradlew check` runs `koverVerify`, which fails under 90%.
- `xvfb-run ./gradlew integrationTest` IDE Starter + UI Driver tests: install the built ZIP in a real IDE, type prompts, answer permission prompts, press Stop, use the pickers, run two sessions from the sidebar, open the MCP panel and sign in, use the slash palette and run a `! command` against a fake CLI (`src/test/resources/fake-claude.py`). Slow; catch plugin-classloader and UI problems the platform tests cannot. On Windows, run `gradlew.bat integrationTest` without `xvfb-run`.
- Test hooks (system properties): `tandem.claudePath` is the `claude` to run (the test tasks point it at the fake CLI); `tandem.configDir` replaces `$CLAUDE_CONFIG_DIR` / `~/.claude` when looking for transcripts; `tandem.browserOpener=log` writes `{"type":"__browse__","url":…}` to the fake's log instead of opening a browser (`Browse connectors` too); `tandem.addFolder=<path>` makes the `Add folder` chooser return that path; `tandem.ideTestShard=<index>/<total>` (index from 0) makes `integrationTest` run only the tests whose position in their class, sorted by name, is index modulo total (`IdeTestShard`; CI splits the IDE test into jobs with it), and a malformed value fails the tests; `-Dtandem.ideHome=<dir>` on the Gradle command line makes `integrationTest` and `demoRecord` run an IDE of the same release already unpacked there (the Gradle cache's `idea-<version>`) instead of downloading and unpacking one under `out/ide-tests` (about 5 GB).
- The fake CLI (see its docstring) reads `TANDEM_FAKE_FIXTURE` (one fixture) or `TANDEM_FAKE_FIXTURES` (comma list, one per spawn), `TANDEM_FAKE_LOG` (its argv and its `CLAUDE*` and `NODE_OPTIONS` environment variables with secrets redacted, then every frame the host writes), `TANDEM_FAKE_SESSION_ID`, `TANDEM_FAKE_DELAY_MS`, `TANDEM_FAKE_GATE_FILE` (holds each `control_request` back until the file exists), `TANDEM_FAKE_LINE_DELAY_MS` (sleeps before each `stream_event` line), `TANDEM_FAKE_AUTH_DONE_MS` (the sign-in flips the server to connected after that many ms) and `TANDEM_FAKE_EXTRA_NEEDS_AUTH` (a second needs-auth server under that name), `TANDEM_FAKE_SKIP_ADD_DIR` (that `--add-dir` folder is left out of every replayed init), `TANDEM_FAKE_QUEUED_DELAY_MS` (a pause after a queued message's `queued` line) and `TANDEM_FAKE_EXIT_AT_END` (exits that many ms after its last line), `TANDEM_FAKE_KEEP_ADD_DIR` (that directory is listed in every replayed init, with or without `--add-dir`), `TANDEM_FAKE_EXIT_DELAY_MS` (once the host closes stdin, sleeps that long before exiting), `TANDEM_FAKE_RESULT_GATE_FILE` (holds each replayed `result` back until the file exists) and `TANDEM_FAKE_EDIT_CANCEL_MS` (a replayed `tools/call` left unanswered that long is withdrawn with `notifications/cancelled`, as the CLI's `MCP_TOOL_TIMEOUT` would). In an `ide-edit*` fixture it serves the CLI's `mcp_message` requests in the recorded order, rewrites the tool result from the host's own reply (and, with `TANDEM_FAKE_LOG`, logs the disk's text at that moment as `__disk__`), withdraws a held call on `interrupt`, and reads `<path>` as its working directory (rules (n) to (p) of its docstring). `fake-claude.cmd` beside it is what the Gradle tasks run on Windows. It answers `initialize` and every `mcp_*` request inline from the fixture's recorded answers; a fixture whose control responses carry `mcpServers` serves them from a server table, and any other answers `mcp_*` with `Unknown subtype`. It answers `get_context_usage` and `get_usage` inline from the fixture's recorded answers (else the CLI's unsupported error), replays a `parity-*` fixture without its control responses, and lists its own `--add-dir` folders in each init. In a `queue-*` fixture it binds the recorded queued-message ids to the host's own user frames, and replays a message's cancelled line only after the host's `cancel_async_message` or `interrupt`. It names, in a result's `user_message_uuids`, the `user` frames it read since its previous result.

## macOS
- `claude` is found, and run, with the login shell's environment, not the IDE's: an IDE started from the Dock or Finder has launchd's minimal `PATH`. `ide/ShellEnvironment.kt` reads it with `EnvironmentUtil.getEnvironmentMap()`, which can block while the platform runs the shell: never on the EDT. After the settings path and `tandem.claudePath`, `ClaudeBinary.detect` searches that `PATH`, then `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, `~/.bun/bin`, `~/.volta/bin`. Settings | Tools | Tandem shows where it found it.
- The CLI keeps its sign-in in the macOS Keychain. That is the CLI's business: Tandem never reads the Keychain (hard rule 3).
- Whatever the shell profile exports now reaches the CLI from a Dock-launched IDE exactly as in a terminal, for example `ANTHROPIC_API_KEY` or `ANTHROPIC_BASE_URL`, which can change how the CLI authenticates and who is billed. Tandem itself never reads those values.
- The CLI keys transcripts on its physical working directory (`/private/tmp/…` for `/tmp/…`, `/private/var/…` for temporary directories), and the default APFS volume ignores case. Tandem resolves the project path's links and compares paths with `Files.isSameFile` (`docs/protocol.md` 11.1); tests compute keys from `toRealPath()`. A test that needs such a volume, or Linux, says so with `assumeTrue`.
- The JDK's `WatchService` polls on macOS; Tandem asks it for its 2 s rate, so a session started in a terminal shows up within about 3 s.
- In the sidebar, Backspace (the Mac's "delete" key, also with Command) asks whether to delete a session, as Delete does.
- CI: the `build-macos` job in `build.yml` runs `./gradlew check` on `macos-latest` for every push to `main` and every pull request push that changes more than docs, scripts, skills, the other workflows, `CODEOWNERS`, `README.md`, `CLAUDE.md` or `LICENSE` (the `changes` job decides, for all the Gradle jobs; `Script tests` always runs). The IDE test runs on a Mac in `macos-ide-test.yml`: nightly, from Actions > macOS IDE test > Run workflow (`gh workflow run macos-ide-test.yml --ref <branch>` once the workflow is on `main`), and on a pull request labelled `macos-ide-test`. On a Mac, run `./gradlew integrationTest` without `xvfb-run`.

## Windows
Each line is **measured** (the probe run 42448947151 or a Windows run of this branch showed it, CLI 2.1.319) or **inferred** (read from the code and the JDK's and CLI's documented behaviour; a tester's report makes it measured).
- `claude` is found with the IDE's own environment: Windows has no login shell for the platform to run, so `ShellEnvironment` is the process environment, the registry's user and system variables as they were when the IDE started (plus what the Toolbox or a terminal added). A `Path` entry or `CLAUDE_CONFIG_DIR` set after that reaches Tandem at the next IDE start, as it reaches Explorer (**inferred**). After the settings path and `tandem.claudePath`, `ClaudeBinary.detect` reads `PATH` under whatever name the environment gives it (`Path` on Windows), drops the double quotes an installer may write around an entry, and searches it for `claude.exe` then `claude.cmd`, then `%USERPROFILE%\.local\bin` (the native installer's `claude.exe`, which that installer does not put on the `Path`: **measured**), `%USERPROFILE%\.claude\local` and `%APPDATA%\npm` (npm's `claude.cmd`; the folder from `APPDATA`, else `<home>\AppData\Roaming\npm`, npm's documented default: **inferred**, the runner's prefix was its own). The bare `claude` there is npm's `#!/bin/sh` shim, which `CreateProcess` refuses with `error=193` (**measured**), so it is never run. A saved path must end in an extension of `PATHEXT` (`.COM;.EXE;.BAT;.CMD` when unset, compared ignoring case): `canExecute` is true for every file on Windows (**measured**), and Settings | Tools | Tandem says `<path> is not something Windows can run (no .exe, .cmd or .bat)`.
- The npm package ships a native `node_modules\@anthropic-ai\claude-code\bin\claude.exe` and its `claude`, `claude.cmd` and `claude.ps1` shims only call it (**measured**, 2.1.319); Tandem runs that `.exe` when it finds the `.cmd`, so the process it holds is the CLI. A `.cmd` with no `claude.exe` in npm's place (pnpm's, yarn's, nvm-windows' shim) is run as it is: the JDK runs it through `cmd.exe` by itself, and the process Tandem holds is then `cmd.exe` with `claude.exe` and `conhost.exe` as children; `Process.destroy()` is `TerminateProcess` on Windows, never a signal, and on the shim alone it leaves both children running (**measured**). Stop closes stdin (the CLI's graceful exit), then kills the shim and every descendant it listed first (**measured**: the test suite's own fake runs through `fake-claude.cmd`, and `closing the project stops every live session` is green). A drive root (`D:\`) cannot be an added folder (**measured**, `FolderCheckTest`): its trailing backslash is the one argument a `.cmd` cannot be handed cleanly.
- Win32 collapses `..` lexically before it follows a link, so `<root>\link\..\x` is `<root>\x` on Windows and the link's target's sibling on Unix (**measured**, `SessionIndexTest`'s Windows sibling); `isProjectPath` believes the file system on each, and the tests say which they assume.
- The CLI runs its Bash tool in Git Bash and reads `CLAUDE_CODE_GIT_BASH_PATH` (**inferred**, from its own error text and documentation); so does Tandem's `! command`: that variable (one that names no file is skipped), then `bash.exe` in a `Path` entry outside `\System32` (that one is WSL's launcher), then `%ProgramFiles%\Git\bin\bash.exe`, `%ProgramFiles(x86)%\Git\bin\bash.exe` and `%LOCALAPPDATA%\Programs\Git\bin\bash.exe`, run as `bash.exe -lc <command>`; with none, `%ComSpec% /c` and the row's, the result's and Claude's first line is `Ran in cmd.exe: Git Bash was not found`. The choice is pure and its tests ran on Windows; a `! command` through a real Git Bash has not (**inferred**). Tandem passes the variable through like every other one.
- The CLI keys transcripts on `process.cwd()` with its drive letter as the parent gave it: started in `D:\a\tandem\tandem` it wrote `projects\D--a-tandem-tandem` (**measured**; `docs/protocol.md` 11.1), and its `init.additional_directories` spelt the same folder `D:/a/tandem/tandem`, so a path from the CLI comes with either separator and Tandem compares through `Path`, never strings. NTFS ignores case, so a key or a `cwd` in other case finds the same folder, and Tandem compares paths with `Files.isSameFile` as on macOS (**inferred**). `user.home` is `%USERPROFILE%` (**measured**).
- The JDK's `WatchService` is native on Windows (`ReadDirectoryChangesW`) and reports deletions (**measured**: `SessionIndexTest`'s watch tests run there); a session started in a terminal shows up within a second (**inferred**). A file another process holds open cannot be deleted (**measured**: the suite's own `The process cannot access the file because it is being used by another process` while a fake still ran); deleting a session whose CLI is writing shows that error in the chat (**inferred**).
- Tests: the platform tests spawn `src/test/resources/fake-claude.cmd` (the Gradle tasks pick it on Windows), which runs `python`, never `python3` (the Microsoft Store alias on a developer's machine: **inferred**; the runner has both).
